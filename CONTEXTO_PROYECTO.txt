2. PETICIÓN ORIGINAL (resumen fiel)
-----------------------------------
El usuario pidió actuar como estudio profesional y construir un juego COMPLETO de
supervivencia zombie 3D low poly para Android, inspirado en el modo Zombies de
Call of Duty pero con identidad, mapas, nombres y recursos originales:
- Godot 4.7.2, GDScript, renderizador Mobile, Android, HORIZONTAL forzado,
  PANTALLA COMPLETA INMERSIVA, controles táctiles, escalabilidad gráfica.
- Low poly de calidad (no prototipo), paleta grises/verdes/marrones + luz cálida +
  acentos intensos.
- CANVA obligatorio para identidad visual e interfaz (logo, menú, fondos, HUD,
  iconos, pantallas). Si no hay acceso, decirlo; nunca fingir.
- HYPER3D RODIN obligatorio para modelos (jugador, zombie normal, corredor,
  blindado, tanque, jefe; armas; props), con rigging y presets de animación
  de Hyper3D. No inventar animaciones.
- FPS por rondas infinitas, puntos, compras (armas de pared, munición, puertas,
  ventajas, máquina de mejoras tipo Pack-a-Punch, caja misteriosa), mapa
  compacto "SECTOR ABANDONADO" (zona inicial, calle, gasolinera, almacén,
  vehículos, barricadas, zona especial con máquina de mejoras, sectores
  bloqueados), barricadas rompibles/reparables, jefe, efectos con pooling,
  HUD, menús (JUGAR/CONFIGURACIÓN/CRÉDITOS/SALIR), carga, pausa, derrota,
  récords locales, sonido original, volúmenes separados, 3 perfiles gráficos
  (BAJO/MEDIO/ALTO), objetivo 30/60 FPS, arquitectura ordenada, pruebas,
  entregables: proyecto, scripts, escenas, modelos, rigs, animaciones, iconos,
  texturas, sonidos, VFX, recursos, instrucciones Android, informe de pruebas,
  ZIP y APK si es posible (sin afirmar nada no hecho).

3. ENTORNO / HERRAMIENTAS (lo que se descubrió)
-----------------------------------------------
- Sesión Claude Code en la nube (contenedor Linux x86_64, sin GPU, sin Vulkan,
  sin dispositivo Android). Xvfb + Mesa llvmpipe permiten renderizar con OpenGL
  (renderizador Compatibility) para capturas.
- Godot 4.7.2 descargado del mirror oficial:
  https://downloads.godotengine.org/?version=4.7.2&flavor=stable&slug=linux.x86_64.zip&platform=linux.64
  (redirige a godot-releases.nbg1.your-objectstorage.com; github.com bloqueado
  por proxy). Plantillas: .../4.7.2-stable/Godot_v4.7.2-stable_export_templates.tpz
  Instalado en /opt/godot, enlace /usr/local/bin/godot. Plantillas en
  ~/.local/share/godot/export_templates/4.7.2.stable/ (solo android*).
- Android SDK en /opt/android-sdk (cmdline-tools, platform-tools,
  build-tools;35.0.1, platforms;android-35). JDK 21 del sistema.
  Editor settings: ~/.config/godot/editor_settings-4.7.tres con
  export/android/android_sdk_path="/opt/android-sdk" y keystore debug de Godot.
  (Todo esto vive en el contenedor, NO en el repo: en un contenedor nuevo hay
  que reinstalarlo.)
- Python: pygltflib, pillow, numpy, scipy, matplotlib (pip). ffmpeg disponible.
- Conectores usados: Hyper3D (Rodin), Canva, Three3D (three.ws), GitHub.
  Higgsfield requería autenticación (no usado). ElevenLabs no se usó.

Trampas técnicas descubiertas:
- Scripts "-s" (SceneTree) que referencian clases del proyecto o autoloads por
  nombre se cuelgan o no compilan → usar load() dinámico o escenas de test (.tscn).
- En _initialize de un SceneTree hay que esperar process_frame antes de hornear navmesh.
- La salida de godot por tubería se pierde si se mata el proceso con timeout.
- set_anchors_preset sobre un Control ya en el árbol conserva el rect; usar
  set_anchors_and_offsets_preset.
- Los nombres de hueso importados pueden ser "mixamorig_Head" o "mixamorig:Head"
  (el código prueba ambos).
